# Story mode without input

Part of step 6 of the [whole-game coverage plan](WHOLE_GAME_COVERAGE_PLAN.md): run every Dragon Adventure part and its battles without input, so the code only story mode reaches (its map, its scene scripts, its pre-battle screen, its battle rules) runs and its stops are found. Written 2026-10-19. Names stay neutral; addresses are BT2's.

## What is known (BT2's code and data, checked where noted)

- **Choosing an episode:** the main menu's first entry sets mode 6 or 7; mode 7 is the episode screen (`0x41F880`); mode 8 takes the episode from progress `+48`, plays its opening (`0x4211D8`) and sets progress flag `0x200`, after which main runs `0x2A8A38` instead of the versus battle routine.
- **Episodes and parts:** an episode table in the executable (`0x344F30`, 16 bytes per episode: an available flag, the number of parts, the map file 15879 Earth or 15880 Namek) lists **25 episodes with 207 parts**. Episode 23 is marked unavailable (flag 0).
- **Scenes:** each part has three consecutive scene files; the first is **33 + 3 × (parts before it)** (`0x2AC580`; progress `+52` is the part). A scene file is a script: `GSCF`, with sections `GSHD`, `GSCD` (code: `GSAC` blocks numbered `0xFFFFFFFF` for the start and 1000, 1001, 2001 to 2025, 3001 to 3003, each ending in `EOFC`) and `GSDT`. An instruction word holds the opcode in its upper 16 bits and the argument count in bits 8 to 15; each argument word holds `(value << 8) | type` (type `0x0A`: an integer). All 621 scene files (33 to 653) decode.
- **The story loop:** `0x2A8A38` runs `0x2AC520`: the map (`0x2AC308`: per scene, load its file, hand it to the script machine `0x29F518`, set it up `0x2ACF90`, then each frame update the map `0x2ACB20` and check for an event `0x2AC1F8`), then, unless the episode is over (`0x2AC9A8`), the pre-battle screen (`0x2AC450` → `0x255EA0`, which waits for a confirmation `0x243BA8` and then calls the same battle setters as `BT2_START_BATTLE`), the battle routine `0x103000` and an after-battle step (`0x2AC4A0`), in a loop.
- **Events** (`0x2AC1F8`, state at `0x3B26B0`: phase, kind, number): kinds 2 to 4 make the number the next scene (`0x2ACE58`), set by opcodes 1004, 1007, 1012 and 1013; kind 1 ends the map without a scene change (opcode 1011, which also gives an item: see towns below).
- **The script machine:** about 100 functions at `0x29E000`-`0x2A1000`; the map's setup (`0x2AB878`) registers the command table (`0x344C98`, about 90 opcodes in groups of a thousand) and also loads file 13259. Opcodes the scene files use: below 1000 (the machine's own instructions), 1002 (stores its argument in the story state), 1003, 1005, 1009 (adds its argument to a set of up to five: likely the map's open events or markers), 1010, 1012, 1013, and the groups 4001-4008, 8001-8010, 9001, 10004-10009, 11001, 12001-12004, 13001-13007, 15001.
- **Map markers (found 2026-10-19):** the map's frame loop (`0x2ABF30`) runs until the scene's script ends or the map mode's exit test (`0x2AD898`, from a callback table) says so. The exit test asks whether the player has reached a marker (`0x20C870`, a byte of the map object) and which (`0x20C8E8`), runs that marker's block of the scene script (block 2000 + marker, `0x2AD1F0`), whose command 1002 names the next scene, then fades out and ends the map. Command arguments index the script's values (section `GSDT`), which hold the map file, the lead character's models and the markers' scenes. On some maps (a flag the exit routine tests) the marker's block is 3000 + marker instead (episodes 3, 4, 7 and 22). **193 of the 207 parts have a marker that leads to their own story scene** (first scene + 1); 7 more go there from their first scene without a marker (command 1012 in block 1001); the remaining 7 are episode 23, which the game marks unavailable.
- **Checked:** `BT2_START_EPISODE=<episode>[,<part>]` starts episodes 0 to 24 (each loads its 3D map, nothing interpreted; episode 23's first scene is empty, matching its unavailable flag). With `,marker:<m>` a tool-only replacement of the two marker queries reports the player at marker *m* once: episode 0 part 0 with marker 14 leaves the map for scene 34, the episode's opening cutscene (Piccolo, "Five peaceful years have passed..."), which then runs without input (text boxes: see below). On the way it sent SOUNDS request `0x80`, now implemented from the module's code (handler `0xF2C`: load a bank into an existing slot, keeping the bank count). `tools/ps2recomp/story_scenes.py` lists per part the markers, the marker to the story scene, the scenes reached and the commands used ([VALIDATION.md](../../progress/VALIDATION.md)).

- **Waits for a button (found 2026-10-19):** the game keeps per pad a processed state at `0x3B0B00 + 384 × port` (`+0x130` held, `+0x134` pressed this frame, `+0x144` repeating); story mode's waits test port 0's pressed word (`0x3B0C34`) for cross in a function called once per frame: the scene script's message command 13004 (`0x2A7400`, in its update phase 2, only once the text is fully shown), the pre-battle screen's input step (`0x255580`), the after-battle results (`0x2581F0`) and the yes/no dialogue (`0x29C640`, cursor at `+88` of the structure at `0x387DA0`; left in the repeating word moves it to Yes).
- **The pre-battle screen** (structure at `0x3879D0`, state at `+364`): state 0 lists the team's slots (`+416`, 20 bytes each, -1 when empty; `+616` slots, `+624` filled, cursor `+360`); cross on an empty slot picks a fighter (state 1), on a filled one opens a two-item menu (state 2: customisation, or "start" once every slot is filled, which asks for confirmation, state 3). Down in the repeating word moves the cursor.
- **After the battle:** the story loop's after-battle step (`0x2AC4A0`) runs the results through `0x2582E8`, which returns nonzero when the battle was cleared (the story goes on; the save flow `0x2587A8`, state at `+20` of `0x387A00`: 9 "Save game data?", 21 "Exit saving?", both with the cursor on No) and zero when it was lost (the part is reset for another try, no save flow).
- **A whole part without input (2026-10-19):** the episode starter answers these waits (every 30 calls of a waiting function one call sees cross pressed, and the game's own test decides; on the pre-battle screen it moves down to the next empty slot; on "Exit saving?" it first presses left, so nothing is saved) and ends the run 300 flips after the after-battle step, recording cleared or lost; a screen pressed past its limit counts as stuck and ends the run. Episode 0 part 0 runs map → marker 14 → the opening cutscene → the pre-battle screen (Piccolo against Raditz) → the battle → "CLEAR!!" → no save → the next part's map, in 4,543 flips. A sample of 8 parts (episodes 0, 1, 6, 9, 13, 17, 21, 24) all reached and finished their battle, nothing interpreted: 1 cleared, 7 lost (the player's side gets no input); 4 at a time they took 2 minutes. `tools/ps2recomp/story_sweep.py` runs this per part (`--jobs` for parallel runs).
- **Both sides to the CPU (2026-10-19):** the pre-battle setup (`0x255EA0`) calls the side setter (`0x101AB0`) with control 0 for side 0 (the player) and 1 for side 1 (the CPU); the episode starter passes 1 for both, as `BT2_START_BATTLE` does. The sample of 8 then gave 6 cleared and 2 lost.
- **Chases (found 2026-10-19):** in a chase part the first scene's start block (1001) places the enemy on the map (commands 8002, 8001) and sets event kind 3 with the story scene (command 1013) instead of going there at once (1012, kind 2). While the story state at `0x3B2654` is negative the map's exit test asks only whether the enemy is caught (`0x20C8A0`, byte `+0xA` of the map object, the byte after the marker byte) and then goes to the event's scene. The episode starter reports the enemy caught once, on the map's 120th query, which skips the chase as a marker start skips the flight. `story_scenes.py` marks these parts (`chase`): episode 4 part 4, episode 9 part 5 and episode 17 part 2.
- **The story sweep (2026-10-19):** all 200 parts that can be started finished their battle, nothing interpreted: **73 cleared, 127 lost** (the CPU on the player's side loses many story battles, which are set against it). The first run, 6 parts at a time, took 56 minutes; 4 parts stopped and were rerun after the chase change: the 3 chases (they had waited on the map) and episode 0 part 5, whose battle has no time limit and needed 23,447 flips (budget 40,000 instead of 15,000).

## Map content besides the story marker (the user's description, 2026-10-19)

- **Optional markers:** fights, and conversations with other characters on the map. In the scene files the first scene's other marker blocks lead to scenes beyond the 621 story scenes (episode 0 part 0: markers 5, 7, 8, 11 and 21 to scenes 664 to 734).
- **A shop** the player can use on the map.
- **In the places optional markers lead to:** item pickups, Dragon Ball pickups, characters to talk with who can give items, and some to fight.

What the game does (found 2026-10-19):

- **Towns:** an optional marker leads to a town scene (Eastern Capital, Baba's Palace, Kami's Lookout, Hercule City, ...): a small map with its characters (map objects 3 to 11) and "R1 To World Map" (reaching a marker in a town leaves it: `0x2A9E30`, event kind 4). 436 marker cases lead to 73 distinct town scenes. The town step (`0x2A99B8`) runs a character's block of the scene script (numbered from -2 down, through `0x2AD368`): the first character's when the player is in reach (bit 0 of `0x20C950`) and presses cross, the others' when the player touches them (bit *k* of `0x20C980`). A block runs while the script state's running block (`0x3B2664`) is nonzero. Every town has a talk block (-2, messages); 46 have a second block (-3). That block gives an item or starts a fight:
  - **Items (the user: gifts and Dragon Ball pickups):** command 1011 (`0x2A7080`) sets event kind 1 with the item and shows the "GET!!" banner (`0x2A6F98`; phase 0 shows it, phase 2 waits for cross). Items 356 to 362 are the seven Dragon Balls (each in two or three towns; the ball appears in its slot beside the Zeni count).
  - **Fights:** in 41 towns touching the second character leads to a battle through the story loop (pre-battle screen, battle, results), then back to the episode's map; 25 of these blocks have no command 1011, so how the block starts the fight is not decoded yet (the script machine's own instructions).
- **The shop:** scene 664 (Baba's Palace, behind 132 markers) is the item shop: its first character's block runs command 1008 (event kind 7), which opens the shop. The shop's step (`0x247638`, state at `+0x1288` of the structure at `gp-0x4498`) shows messages that take cross once their text is shown (states 2, 21, 22: the first visit's greeting and member's card); its main menu (`0x246860`) opens the buy or sell list on cross and closes the shop on triangle (`0x1000`); the lists go back on triangle.
- **The starter in a town:** the "GET!!" banner's update is one of its waits; after 120 town frames it goes through the characters in turn, reporting the current one in reach (with cross pressed every 30 calls) or touched until its block has run, or for at most 150 calls if it does not answer; after the last one the run ends. In the shop it presses cross on the messages, cross once in the main menu (into the buy list), then triangle until the shop closes. The report's `starter_scenes` lists the scenes a run went to, `starter_town_blocks` the character blocks that ran. `story_sweep.py --optional` runs one case per town scene, from the first part and marker that lead there.
- **Checked:** episode 0 part 0's five optional markers: three towns whose conversation ran, a town (scene 665) whose second character starts a fight (cleared, then back to the episode's map, scene 33), and the shop: greeting, member's card, the buy list (empty), back, the farewell, the town. **The optional sweep** (`story_sweep.py --optional`, 6 at a time, 25 minutes plus a rerun): all 73 town scenes ran to their end, nothing interpreted: 32 towns with conversations, items and Dragon Balls (all seven balls among them), 41 fights (14 cleared, 27 lost).
- **Chases:** in some episodes an enemy has to be chased across the map before the fight (found: three parts; the starter skips the chase itself, see above).

## Battle rules, rewards and sagas (found 2026-10-19)

- **A part's battle record:** script command 1010 (`0x2A7ED8`) fills the record at `0x3B26E8` from its arguments: the battle's settings (`+0` to `+0x10`; `+0xC` the rule kind), the Zeni (`+0x14`), two reward items (`+0x18`, `+0x1C`, -1 for none) and the teams. The pre-battle setup passes `+0` to `+0xC` to the battle setter `0x101A60` (system structure `+0xB8`: kind 1 story, `+0xC0` the time limit, `+0xC8` the rule kind).
- **Rule kinds:** the battle start (`0x101BF0`) turns the rule into flags (`+0xD8`): rule 2 sets 1, rule 3 sets 2. At the battle's end (`0x101D78`) a win sets the result's reward flag (`0x10000` in the finish word, `+0x484`); with flag 2 a loss still counts as cleared, so the story goes on, but without the reward flag. Rule 1 makes the battle won when the time runs out (`0x105BA8`).
- **Sagas are Z-items:** the episode screen lists episode *e* when item 390 + *e* is owned (save block `+0x2548` + 4*e*, the count; episode 23 is never listed). The results (`0x256F10`) give the record's reward items when the reward flag is set; a new item from 390 to 414 also sets the save's notice bit 4 (`+8`). **The special condition is winning a battle the story lets you lose** (rule 3): episode 0 part 0 (Piccolo against Raditz) has rule 3 and the reward item 411; the CPU's win gave item 411, so episode 21 becomes available. The user's 100% save owns all of items 390 to 414 except 413 (episode 23).
- **Dragon Balls inside a fight:** in a story battle the battle start places the first Dragon Ball the player does not own (`+0xD0`: 1 to 7; 8 when all are owned, then one of the items 8 to 11, as in versus battles with the items option). The ball appears when a stage object that can hold it breaks (stage objects `gp-0x4340`; flag `0x20000000` at `+0x34`, `0x274050`; spawn `0x2425D8`), and the player's side picking it up (`0x2423F8` → `0x242218`) records it in the result (`+0x4C8`); after a win the results give item 355 + ball.
- **Stage destruction:** objects take damage (`0x274630`) and break (`0x274338`) from the fighters' hits (`0x11C288`, `0x11D3A0`). In 16 CPU battles, one per stage, objects took damage on 7 stages and broke on 7 others; no item spawned (none of the broken objects held one).
- **The story sweep with the records (2026-10-19):** all 200 parts reached their battle's end (62 cleared, 138 lost; episode 0 part 5, rule 2 and no time limit, needs a 40,000-flip budget), nothing interpreted. Rules: 187 battles rule 0, 9 rule 1, 1 rule 2, 3 rule 3. Each episode's last battle gives the next episode's saga item (391 to 410) and the three rule-3 battles (episode 0 part 0, 4 part 1, 14 part 1) give items 411, 412 and 414 (episodes 21, 22, 24: the special sagas); the CPU's wins unlocked 392, 395, 401, 408 and 411. Stage objects broke in 112 parts, an item spawned in 98, and in episode 13 part 3 the player's side picked up Dragon Ball 1 (the battle was lost, so the ball was not given).
- **Progress kept in the save:** one byte per part from save block `+0xC` (200 parts, episode 23 has none): 0 not cleared, else 1 + a grade from the story state (`progress +0x38`), shown on the episode screen as one of four icons; the completion percentage counts the nonzero bytes. These bytes and the story state (`0x3B2600`, to `+0xD8`) are written only when the save flow saves (`0x258418`), so the starter's runs, which never save, leave them unchanged; the rewards and the Zeni are written at the results.
- **The episode starter's report** lists each battle (`starter_battles`): rule, flags, the ball placed and picked up, result and finish words, the rewards, cleared, and the saga items owned after the results that were not before. `story_sweep.py` writes them to `battles.json` (`--watch` adds the listed functions each part entered).

## What is missing

- **Lost battles:** with the CPU on both sides 127 of 200 story battles are still lost; a lost part does not reach the save flow or the next part's map. Each part is started on its own, so its scenes and battle are covered either way; the save flow after a win is covered by the 73 cleared parts.
- **The chase itself** (the enemy flying across the map, and how the game decides it is caught) runs only until the starter reports it caught.
- **Fight blocks:** how a town's second character starts its fight is not decoded (the runs reach the fights all the same).
- **Pickups outside the towns' scripts:** none found in the scene files; if the overworld map has pickups of its own, they need the map object's code first.
- Waits for a button that runs reach beyond those above: add each to the starter's table (`runtime/probe/game_starter.cpp`).
