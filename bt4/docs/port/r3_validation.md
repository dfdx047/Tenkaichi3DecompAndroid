# 0.1.39.5 R3 validation, in progress

R3 starts from public R2 f103106 and the preliminary hotfix commit 3ba89ba. It excludes the standalone Tag Team menu and developer control UI. At the user's subsequent request, the public receiver supports shared online development rules controlled by the separate Dev client; those rules affect every fighter equally.

## Confirmed regressions and changes

- A six-fighter water-stage test crashed reading address 0x89 in EftWaterSpray_Update. Water wakes still had a two-entry allocation, while EftWater_SetWake accepted additional actor object IDs. The adjacent particle lists were overwritten. The allocation now has ten bounded slots, and reset/update cover the active roster. The identical Vegeta Blue versus Cell scenario completed Niagara Pummel after the change. The storage increase is 96 bytes per water module. A canary test covers 2, 4, 6, 8 and 10 actors and invalid IDs.
- The renderer palette cache read sixteen columns for PSMT4, while decoding read two rows of eight. The production-cache test mutates all sixteen displayed colours, unrelated neighbouring entries and upload generations. This is independent of GPU texture sharing.
- An HD replacement could retain a queued software-artwork enlargement. Arrival of the pack now cancels that work. Cache compaction clears/rebuilds address aliases.
- Modern HUD exit fading now retains native HUD suppression until the custom HUD disappears. Only exact stock scripts are upgraded in memory; edits and saved mod settings remain intact.
- The previous motion-profile migration forced interpolation on despite a saved zero. It has been removed. History buffers are allocated lazily and have allocation-failure coverage. This does not disable interpolation for users who selected it.
- Indexed texture min/max scanning has a SIMD implementation with byte-for-byte interval parity against the scalar version. It adds no texture residency cache.
- HD mip copies are allocated before any GPU upload is queued, so an allocation failure keeps the prior image. Tests cover each failed mip allocation and failed texture creation.

- The buffered xBRZ colour table could be destroyed at process exit before the earlier registered artwork-worker join. A standalone real-worker shutdown probe failed with access violations in three out of three runs. The direct colour-distance mode avoids that process-global 64 MiB table. The same shutdown probe now passes three out of three runs. Existing artwork output/alpha/cache tests also pass. The utility uses direct colour distances; automatic native artwork enlargement was subsequently disabled to retain the ISO artwork. Installed HD assets are unchanged.
- BT4's native tournament input compares tournament ID 1, whereas the reconstructed BT3 handler compared ID 4. All ten cursor/form/item/costume branches and the direction-arrow state now use BT4's lock in PORT builds. Production-handler tests cover all five tournament IDs. A hidden real-menu run for ID 4 moved the cursor from column 1 to 2 and exited normally after the artwork shutdown fix.
- Ginyu now exchanges both participants' characters, costumes and exact current/max HP after the original hit cinematic. The sequential model loader retries queue saturation, and only those participants are protected while loading. Current HP is not replenished. Tests cover dead-victim cancellation, controls, unrelated actors, queue backpressure and non-adjacent/reverse actor ordering. Native 1v1, reversed 1v1 and six-actor Tag Team runtime cases completed. In the non-adjacent Tag case actors 2 and 5 returned to combat with 27,660 and 8,000 HP respectively, still exact 120 blanks after recovery. Native 1v1 and Tag online exchanges also completed with matching HP on both peers. The final shared-rule protocol now requires sim6.

## Memory policy

The CPU pack-image cache retains its separate 512 MiB budget and trims only after crossing its high watermark. The background decoder now pauses once one completed image exceeds that budget; it cannot drain its entire backlog while the renderer is inactive. Eviction remains on the consuming renderer thread so borrowed image data is not freed by the worker. A real asynchronous-decoder test pauses consumption, verifies the bound and resumes all 64 requests. Renderer texture storage is tracked as entries are created/replaced and has a 192 MiB soft working-set target. Entries referenced by the recent four frame lists stay alive, so the active scene may exceed this target. These figures are cache budgets, not a bound on total process memory. The requested removal of cross-address GPU replacement sharing, custom queued-frame fences and the enhanced lighting experiments is retained. A separate off-screen UI test exposed unpaced submissions without swapchain acquisition: the control peaked at 3503.7 MiB. Waiting for GPU completion only when no normal swapchain texture is acquired (or when using a private capture target) reduced the matching control peak to 805.0 MiB. Visible swapchain presentation keeps normal driver pacing and does not use that wait. These off-screen comparisons are not presented as a visible-play FPS improvement.
